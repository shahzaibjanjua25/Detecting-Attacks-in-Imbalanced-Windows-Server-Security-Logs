## Abstract

Detection engineering for Windows Server environments is fundamentally constrained by extreme class imbalance: malicious events typically represent less than 2% of total security telemetry. This project presents a reproducible benchmark and comparative evaluation of machine learning approaches for Windows Security event detection under this constraint.

We generate a controlled synthetic dataset of **50,000 Windows Security events** with a **realistic 2.9% attack ratio** covering six MITRE ATT&CK techniques, and we engineer 12 features with strict train/test separation to prevent target leakage. We evaluate four approaches: a majority baseline, Naive Bayes, XGBoost with class weighting, and Isolation Forest.

**Key result:** XGBoost with class weighting achieves the best F1-score (**0.438**) and PR-AUC (**0.667**), substantially outperforming Naive Bayes (F1 = 0.214) and Isolation Forest (F1 = 0.168). Accuracy alone is misleading: a trivial majority baseline achieves **97.1% accuracy** while detecting **zero attacks**.

## Problem

Windows Security logs are extremely imbalanced. In real-world SOC environments, malicious events typically represent **less than 1–2%** of total security telemetry. This has two consequences:

1. **Accuracy is misleading.** A trivial classifier that always predicts "benign" achieves accuracy above 97%, yet detects nothing.
2. **Models trained naively are biased toward the majority class.** They miss the minority events that matter most — the actual attacks.

This project evaluates whether machine learning models can provide *operationally useful* detection under these realistic conditions.

---

## Dataset

A synthetic dataset of **50,000 Windows Security events**, generated by a reproducible Python script with a fixed random seed.

| Class   | Count  | Percentage |
|---------|--------|------------|
| Benign  | 48,534 | 97.1%      |
| Attack  | 1,466  | 2.9%       |
| **Total** | **50,000** | **100%** |

**Covered MITRE ATT&CK techniques:**

| ID    | Technique                | Event IDs          |
|-------|--------------------------|--------------------|
| T1046 | Network Service Scanning | 4624, 4625, 4648   |
| T1003 | OS Credential Dumping    | 4672, 4624, 4688   |
| T1047 | WMI Execution            | 4688               |
| T1078 | Valid Accounts           | 4720, 4732, 4672   |
| T1070 | Indicator Removal        | 1102, 1100         |
| T1110 | Brute Force              | 4625, 4624         |

**Design principles:**

- **Realistic class imbalance** — 2.9% attack ratio, consistent with real SOC environments.
- **Overlapping feature distributions** — benign and attack messages have similar length distributions, so models cannot trivially discriminate by message length.
- **Label noise** — 1% of labels are randomly flipped to simulate real-world mislabeling.

> **Note:** This is a **controlled benchmark**, not real-world data.  
> Real-world deployment requires validation on production logs.

## Methodology

### Feature Engineering (12 features, no target leakage)

| Category    | Feature              | Description                              |
|-------------|----------------------|------------------------------------------|
| Temporal    | `hour`               | Hour of day (0–23)                       |
| Temporal    | `day_of_week`        | Day of week (0–6)                        |
| Temporal    | `is_weekend`         | Weekend indicator                        |
| Temporal    | `is_business_hours`  | 9–17 on weekday                          |
| Event       | `event_id`           | Windows Event ID                         |
| Event       | `logon_type`         | Logon type                               |
| Event flag  | `is_auth_event`      | Auth event indicator                     |
| Event flag  | `is_privileged_event`| Privileged event indicator               |
| Event flag  | `is_rare_event`      | Rare event ID (from train only)          |
| Text        | `message_length`     | Message character count                  |
| Text        | `word_count`         | Message word count                       |
| Temporal    | `is_unusual_hour`    | Unusual hour (from train only)           |

### Preventing Target Leakage

1. **Split before engineering** — 80/20 train/test split performed *before* any feature is computed.
2. **Training-only thresholds** — derived features (`is_rare_event`, `is_unusual_hour`) use statistics from the training set only.
3. **No test-set influence** — test set is never used for feature engineering or model selection.

### Models Evaluated

| Model              | Type              | Notes                                          |
|--------------------|-------------------|------------------------------------------------|
| Majority Baseline  | Dummy             | Always predicts "benign"                       |
| Naive Bayes        | Probabilistic     | Assumes feature independence                   |
| **XGBoost**        | Gradient Boosting | With `scale_pos_weight` for class imbalance    |
| Isolation Forest   | Unsupervised      | Anomaly detection via random partitioning      |

### Evaluation Metrics

- **Accuracy** — reported to demonstrate it is misleading.
- **Precision, Recall, F1** — standard classification metrics.
- **PR-AUC** — *primary metric* for imbalanced data.
- **ROC-AUC** — reported for completeness.

## Key Findings

1. **Accuracy is misleading.** The majority baseline achieves **97.1% accuracy** — the highest of all models — while detecting **zero attacks**. Accuracy is not a valid metric under class imbalance.

2. **XGBoost with class weighting is the best model.** It achieves the highest F1-score (**0.438**) and PR-AUC (**0.667**), roughly **2×** the F1 of Naive Bayes (0.214) and **2.6×** the F1 of Isolation Forest (0.168).

3. **Naive Bayes fails on imbalanced data.** Despite being the original paper's "best" model, its F1 = 0.214 and recall = 0.222 are operationally insufficient for SOC deployment.

4. **Authentication events are the strongest signal.** `is_auth_event` accounts for **45.4%** of XGBoost's feature importance, consistent with real-world adversary behavior — both brute force (T1110) and network scanning (T1046) produce authentication events.

## Limitations

This project has four significant limitations.

1. **Synthetic data.** The dataset is a controlled benchmark. Real-world Windows Security logs contain substantial noise, complex context, and attack patterns not represented here.
2. **Limited technique coverage.** We simulate 6 of 200+ MITRE ATT&CK techniques. Coverage of persistence, exfiltration, and other techniques may exhibit different feature importance profiles.
3. **Single environment.** The dataset reflects a single synthetic Windows Server 2016 environment. Generalization to other versions, configurations, and topologies is untested.
4. **No temporal validation.** Our train/test split is random. Real SOC deployment involves temporal drift, where models are trained on past data and applied to future data.

---

## Future Work

Four directions are promising.

1. **Temporal validation.** Train on earlier periods and test on later periods to measure concept drift.
2. **Ensemble methods.** Combine Naive Bayes, XGBoost, and Isolation Forest via stacking or weighted voting. Preliminary experiments suggest recall improvements of 10–15% while maintaining precision.
3. **Real-world datasets.** Extend the framework to public datasets (e.g., COMISET, TON_IoT) and, where possible, to production-derived Windows Security logs.
4. **Cost-sensitive learning.** Assign explicit costs to false positives and false negatives based on SOC analyst time and breach impact, and optimize the decision threshold accordingly.
